# cheongyak-bot

[![daily-report](https://github.com/3dagger/cheongyak-bot/actions/workflows/daily-report.yml/badge.svg)](https://github.com/3dagger/cheongyak-bot/actions/workflows/daily-report.yml)

청약홈, LH청약플러스, SH 인터넷청약에 올라오는 분양·임대 공고를 모아서 매일 아침 텔레그램으로 보내 주는 스크립트입니다.

세 사이트를 매일 따로 들어가 보기 번거로워서 만들었습니다. GitHub Actions에서 돌기 때문에 서버나 켜 둔 PC가 없어도 되고, 파이썬 표준 라이브러리만 써서 설치할 패키지도 없습니다.

## 받는 메시지

```
🏠 청약 데일리 리포트 · 10/27(화)
🆕 새 공고 2 · 👶 특공 2 · 📬 오늘 2 · ⏰ 마감 1

━━━━━━━━━━━━
🆕 새로 올라온 공고 (지난 리포트 이후)

▪️ ○○자이
   서울 · 민영 1,024세대 · 분상제
   📅 특공 11/3 → 1순위 11/4~11/5 → 발표 11/12
   💰 25평 9.8억 · 34평 13.2억
   👶 신생아 52 · 신혼 104

▪️ △△ 행복주택
   경기 · LH 행복주택
   📅 마감 11/10(화)

━━━━━━━━━━━━
👶 신생아·신혼 특공 접수 예정 (14일 내)

▪️ ○○자이 — 특공 11/3(화) · 1순위 11/4(수)~11/5(목)

▪️ □□ 민간임대
   인천 · 공공지원민간임대 512세대
   📅 접수 10/27~10/29 → 발표 11/3
   👶 신혼 60

━━━━━━━━━━━━
📬 오늘 접수 (시작·마감)

▪️ ◇◇아이파크
   경기 수원시 · 도시형생활주택 120세대
   📅 접수 10/27 → 발표 10/30

▪️ □□ 민간임대 — 접수 10/27(화)~10/29(목)

━━━━━━━━━━━━
⏰ 내일 마감

▪️ ☆☆ 국민임대 예비입주자
   경기 · LH 국민임대
   📅 일반 10/19(월)~10/28(수)
```

섹션별로 이렇게 고릅니다.

- 새로 올라온 공고: 지난 리포트 이후 처음 보이는 공고입니다. 하루 실행이 빠지거나 API에 공고가 늦게 올라와도 다음 리포트에 나옵니다.
- 신생아·신혼 특공 접수 예정: 신생아·신혼부부 특별공급 물량이 있고, 14일 안에 접수가 시작되는 단지입니다.
- 오늘 접수 (시작·마감): 특공, 1순위, 일반 접수 중 하나라도 오늘 시작하거나 오늘 끝나는 단지입니다. 접수는 대부분 하루뿐이라, 오늘 넣어야 하는 단지가 여기에 모입니다.
- 내일 마감: 접수가 내일 끝나는 단지입니다. 내일 하루만 접수하는 단지도 여기에 나옵니다.

폰 화면에서 줄이 넘어가지 않도록 공고 한 건을 줄마다 나눠 씁니다. 공고명, 지역과 유형, 📅 일정, 💰 분양가, 👶 신생아·신혼 특공 세대수 순서입니다. 맨 위 두 번째 줄은 섹션별 건수라서, 알림 미리보기만 봐도 오늘 볼 게 있는지 알 수 있습니다.

공고명을 누르면 원문 공고가 열립니다. `[정정공고]`, `입주자 모집 공고`, `('26.11.18.)`, 끝의 `공공분양주택` 같은 군더더기는 지우고, `(부천대장지구 A2BL)`처럼 블록 번호가 든 괄호는 `A2BL`만 남깁니다. 40자가 넘으면 자릅니다.

일정이 한 단계뿐이면 `접수 10/27(화)~10/29(목)`처럼 요일까지 쓰고, 여러 단계면 요일을 빼고 `특공 11/3 → 1순위 11/4~11/5 → 발표 11/12`처럼 화살표로 잇습니다. 오늘·내일 섹션에서는 그 섹션에 올라온 이유가 된 접수 단계를 굵게 표시합니다.

한 공고가 여러 섹션에 해당하면 처음 나오는 섹션에서만 자세히 나오고, 그다음부터는 `▪️ ○○자이 — 특공 11/3(화)`처럼 그 섹션에 해당하는 일정만 한 줄로 나옵니다.

경기·강원 같은 도 지역의 청약홈 공고는 `경기 수원시`처럼 시·군까지 표시합니다. LH 공고는 목록에 주소가 없어 도까지만 나옵니다.

💰는 전용면적별로 가장 비싼 주택형의 분양가입니다. 평은 흔히 말하는 "34평"처럼 공급면적(전용+주거공용)을 3.3058로 나눠 반올림한 값이라, 같은 84㎡도 단지마다 33~36평으로 달라질 수 있습니다. 공급면적이 없으면 전용면적(㎡)으로 씁니다. 평형이 5개 이상이면 가장 작은 평형과 가장 큰 평형만 나옵니다. APT 공고에만 붙습니다.

"분상제"는 분양가상한제가 적용된 단지에 붙습니다. "발표"는 당첨자 발표일입니다. 발표일이 같은 단지에 중복으로 청약하면 무효가 될 수 있으니, 같은 날짜가 보이면 청약 전에 확인하세요. LH·SH 공고에는 나오지 않습니다.

소식이 없는 날에는 "소식 없음" 한 줄만 옵니다.

## 어디서 가져오나

| 출처 | 대상 | 방식 |
|---|---|---|
| 청약홈 | APT(민영·국민·신혼희망타운), 무순위·잔여, 임의공급, 도시형생활주택·생활숙박시설·민간임대, 공공지원 민간임대 | 공공데이터포털 API |
| LH청약플러스 | 분양주택, 임대주택(행복·국민·영구·매입·전세 등), 주거복지 | 공공데이터포털 API (토지·상가 제외) |
| SH 인터넷청약 | 분양·임대 게시판의 입주자 모집 공고 | 게시판 HTML 파싱 (지역 필터에 서울이 있을 때만) |

오피스텔 공고는 리포트에서 뺍니다. 다시 받으려면 `cheongyak_report.py`의 `EXCLUDE_HOUSE_TYPES`를 비우면 됩니다.

LH 공고는 상세정보 API로 공급 대상별 접수일(특공·일반 등)과 신생아·신혼 특공 여부를 가져옵니다. 세대수는 나오지 않아서 "신생아 특공"처럼 있다는 것만 표시합니다. LH 공공분양은 청약홈에도 올라오는데, 같은 단지는 하나로 합쳐서 세대수는 청약홈, 접수 일정은 LH 것을 씁니다.

SH 공고는 게시일만 알 수 있으니 접수 일정은 공고문에서 확인해 주세요.

## 설치

필요한 것은 GitHub 계정, 공공데이터포털 계정, 텔레그램입니다. 키 승인 대기 시간을 빼면 15분 정도 걸립니다.

### 1. 레포 가져오기

이 레포를 Fork 합니다. 포크한 레포에서는 Actions가 기본으로 꺼져 있으니, Actions 탭에 들어가서 워크플로를 켜 주세요.

공고 기록을 남에게 보이고 싶지 않다면 클론한 뒤 본인 private 레포로 올려도 됩니다. 하루 1분 정도라 무료 사용량 안에서 충분히 돕니다.

```bash
git clone https://github.com/<본인 계정>/cheongyak-bot.git
cd cheongyak-bot
cp .env.example .env
```

### 2. 공공데이터포털 API 키

[공공데이터포털](https://www.data.go.kr)에 로그인한 뒤 아래 세 서비스를 각각 활용신청합니다. 모두 자동 승인입니다.

- [한국부동산원_청약홈 분양정보 조회 서비스](https://www.data.go.kr/data/15098547/openapi.do)
- [한국토지주택공사_분양임대공고문 조회 서비스](https://www.data.go.kr/data/15058530/openapi.do)
- [한국토지주택공사_분양임대공고별 상세정보 조회 서비스](https://www.data.go.kr/data/15057999/openapi.do)

인증키는 계정에 하나라서 세 서비스가 같은 키를 씁니다. 마이페이지에서 일반 인증키의 **Decoding** 값을 복사해 `.env`의 `CHEONGYAK_SERVICE_KEY`에 넣습니다. Encoding 값을 넣으면 두 번 인코딩돼서 인증 에러가 납니다.

신청 직후에는 "등록되지 않은 인증키" 에러가 날 수 있습니다. 보통 1~2시간 안에 풀립니다.

### 3. 텔레그램 봇

1. 텔레그램에서 [@BotFather](https://t.me/BotFather)에게 `/newbot`을 보내 봇을 만들고 토큰을 받습니다.
2. 토큰을 `.env`의 `TELEGRAM_BOT_TOKEN`에 넣습니다.
3. 방금 만든 봇과 대화를 열어 아무 메시지나 보냅니다.
4. 아래 명령으로 채팅방 ID를 확인해서 `TELEGRAM_CHAT_ID`에 넣습니다.

```bash
python3 cheongyak_report.py --get-chat-id
```

가족과 같이 받고 싶으면 그룹방을 만들어 봇을 초대하고, 그룹방에 `/start`를 보낸 뒤 같은 명령을 실행하면 됩니다. 봇은 그룹에서 `/`로 시작하는 메시지만 받기 때문에 일반 메시지로는 ID가 안 잡힙니다. 그룹방 ID는 `-`로 시작합니다.

여기까지 됐으면 로컬에서 먼저 확인해 봅니다. 파이썬 3.9 이상이면 되고, macOS에 기본으로 들어 있는 `python3`로도 돕니다.

```bash
python3 cheongyak_report.py --test      # 텔레그램으로 테스트 메시지
python3 cheongyak_report.py --dry-run   # 보내지 않고 리포트를 터미널에 출력
```

### 4. GitHub Secrets 등록

포크한 레포의 Settings → Secrets and variables → Actions에서 `.env`와 같은 값으로 세 개를 등록합니다.

| 이름 | 값 |
|---|---|
| `CHEONGYAK_SERVICE_KEY` | 공공데이터포털 Decoding 키 |
| `TELEGRAM_BOT_TOKEN` | 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 채팅방 ID |

`gh` CLI를 쓴다면 이렇게 해도 됩니다. 실행하면 값을 입력하라고 나옵니다.

```bash
gh secret set CHEONGYAK_SERVICE_KEY -R <본인 계정>/cheongyak-bot
gh secret set TELEGRAM_BOT_TOKEN -R <본인 계정>/cheongyak-bot
gh secret set TELEGRAM_CHAT_ID -R <본인 계정>/cheongyak-bot
```

### 5. 지역 정하고 첫 실행

받을 지역은 레포 변수 `AREA_FILTER`로 정합니다. 변수가 없으면 `서울,경기,인천`입니다. 다른 지역을 받으려면 Settings → Secrets and variables → Actions의 Variables 탭에서 `AREA_FILTER`를 만들고, 전국을 받으려면 값을 `전국`으로 둡니다.

```bash
gh variable set AREA_FILTER -R <본인 계정>/cheongyak-bot --body "부산,경남"
```

워크플로 파일을 고치지 않으니 원본 레포의 변경을 Sync fork로 받을 때 충돌이 나지 않습니다.

그다음 Actions 탭에서 daily-report를 골라 Run workflow를 누르거나, 아래 명령으로 바로 한 번 보내 봅니다.

```bash
gh workflow run daily-report.yml -R <본인 계정>/cheongyak-bot
```

이후로는 매일 아침 자동으로 옵니다. 예약 시각은 03:17(KST)입니다. GitHub 예약 실행이 몇 시간씩 늦게 시작되어서, 아침에 받으려고 일찍 잡아 두었습니다.

## 설정

로컬에서는 `.env`, Actions에서는 같은 이름의 레포 변수(Variables)로 바꿉니다.

| 이름 | 기본값 | 설명 |
|---|---|---|
| `AREA_FILTER` | `.env`: 비어 있음(전국)<br>Actions: `서울,경기,인천` | 쉼표로 구분한 시·도. 예: `서울,경기,인천`. `서울특별시`·`경기도`처럼 써도 됩니다. `전국`이라고 쓰면 거르지 않습니다. LH의 "전국" 공고는 항상 포함됩니다. 알아보지 못한 이름은 리포트 아래에 ⚠️로 알려 줍니다 |
| `SEND_WHEN_EMPTY` | `true` | `false`면 소식이 없는 날에는 보내지 않습니다 |

받는 시간은 워크플로의 `cron`으로 바꿉니다. UTC 기준이라 한국 시간에서 9시간을 빼야 합니다. 오전 6시 30분에 예약하려면 `30 21 * * *`입니다.

GitHub 예약 실행은 제시간에 시작되지 않으니, 받고 싶은 시각보다 일찍 잡으세요. 이 레포는 지연이 2026년 7월에는 1시간 안쪽이었다가 11월에는 3~5시간까지 늘었고, 분을 정각에서 17분으로 옮겨도 줄지 않았습니다. 그래서 아침 7~8시에 받으려고 03:17(`17 18 * * *`)로 두었습니다. 실제로 언제 시작됐는지는 Actions 탭의 실행 기록에서 볼 수 있습니다. 한국 시간 자정보다 앞으로 잡으면, 지연이 짧은 날에는 전날 날짜로 리포트가 나갑니다.

### 정해진 시각에 받기 (선택)

예약 실행은 2026년 11월에 07:49~12:01 사이로 들쭉날쭉 시작됐습니다. 매일 같은 시각(예: 08:30)에 받으려면 외부 스케줄러가 그 시각에 워크플로를 API로 실행하게 합니다. 수동 실행(`workflow_dispatch`)은 몇 초 안에 시작됩니다.

리포트는 하루에 한 번만 나갑니다. 외부 호출과 예약 실행 중 먼저 돈 쪽이 보내고, 나중 쪽은 `.state/last_sent` 기록을 보고 건너뜁니다. 예약 실행은 외부 호출이 빠진 날의 예비가 됩니다. Actions 탭에서 수동 실행할 때 "오늘 이미 보냈어도 다시 보내기"를 켜면 다시 보냅니다.

1. GitHub → Settings → Developer settings → Fine-grained tokens에서 토큰을 만듭니다. Repository access는 이 레포 하나만, Permissions는 Actions: Read and write만 줍니다.
2. [cron-job.org](https://cron-job.org) 같은 스케줄러에 작업을 하나 만듭니다.
   - URL: `https://api.github.com/repos/<본인 계정>/cheongyak-bot/actions/workflows/daily-report.yml/dispatches`
   - Method: `POST`, Body: `{"ref":"main"}`
   - Headers: `Authorization: Bearer <토큰>`, `Accept: application/vnd.github+json`
   - 시각: 매일 08:30, 시간대 `Asia/Seoul`
3. 성공하면 GitHub가 `204`를 돌려주고 Actions 탭에 `workflow_dispatch` 실행이 생깁니다.

토큰에는 만료일이 있으니 만료되기 전에 새로 만들어 바꿔 주세요. 토큰이 만료돼도 예약 실행이 예비로 돌기 때문에 리포트가 끊기지는 않고 늦게 올 뿐입니다.

## 동작 방식

[cheongyak_report.py](cheongyak_report.py) 한 파일이 전부입니다.

1. 청약홈 API 5종에서 최근 45일, LH API에서 최근 90일 공고를 가져오고 SH 게시판 첫 페이지를 읽습니다.
2. `AREA_FILTER`로 지역을 거릅니다.
3. 아직 접수가 끝나지 않은 공고는 한 번 더 조회합니다. APT와 공공지원 민간임대는 주택형별 API로 신생아·신혼 특공 세대수를 합치고 APT는 평형별 최고 분양가도 가져오며, LH는 상세정보 API로 접수 일정을 가져옵니다.
4. 보낸 공고 기록(`.state/seen.json`)과 비교해 새 공고를 고르고, 나머지 섹션을 날짜 기준으로 나눠 텔레그램으로 보냅니다. 메시지가 길면 공고 한 건이 두 메시지에 걸치지 않게 나눠 보냅니다.

몇 가지 덧붙이면 이렇습니다.

- 보낸 공고 기록과 마지막으로 보낸 날짜(`.state/last_sent`)는 Actions 캐시로 다음 실행에 넘어갑니다. 캐시가 없는 첫 실행에는 공고일이 어제·오늘인 공고를 새 공고로 봅니다.
- "오늘"은 실행하는 기기의 시간대와 상관없이 한국 날짜입니다. 서버가 UTC여도 그대로 돌리면 됩니다.
- LH나 SH 조회가 실패하거나 결과가 0건이면 리포트는 그대로 보내고 맨 아래에 ⚠️ 경고를 붙입니다.
- 같은 경고는 실행 로그에도 남습니다. Actions에서는 실행 페이지의 Annotations에 표시되고, 로그에는 섹션별로 몇 건을 보냈는지도 나옵니다.
- 공고별 상세 조회(3번)가 연달아 3번 실패하면 API 장애로 보고 남은 공고는 조회하지 않습니다. 리포트가 몇 시간씩 늦어지지 않게 하려는 것이고, 못 가져온 건수는 ⚠️ 경고에 나옵니다.
- 청약홈 조회 실패처럼 리포트를 아예 만들지 못하면 "청약 리포트 생성 실패" 메시지와 실행 로그 링크를 보냅니다.
- GitHub는 60일 동안 커밋이 없는 레포의 예약 워크플로를 끕니다. 그래서 실행할 때마다 `gh workflow enable`로 다시 켜 둡니다.

## 문제 해결

리포트가 안 오면 먼저 Actions 탭의 실행 로그를 봅니다. 포크 직후라면 Actions가 꺼져 있을 가능성이 큽니다.

- 실행이 `레포 Secrets에 다음 값이 없습니다`로 실패: 설치 4번의 Secrets 등록이 빠졌습니다. 포크에는 원본 레포의 Secrets가 따라오지 않으니 직접 등록해야 합니다.
- "등록되지 않은 인증키" 또는 401: 활용신청 후 아직 반영이 안 된 경우가 대부분입니다. 한두 시간 기다려 보고, 그래도 안 되면 Decoding 키를 넣었는지 확인하세요. 개발계정 활용기간(24개월)이 끝나도 같은 에러가 나니 마이페이지에서 연장하면 됩니다.
- 리포트 아래에 `⚠️ LH 조회 실패`: LH 분양임대공고문 조회 서비스를 활용신청했는지 확인하세요.
- 리포트 아래에 `⚠️ LH 접수 일정 조회 실패`: LH 상세정보 조회 서비스를 활용신청했는지 확인하세요. 그동안 LH 공고는 마감일만 나옵니다.
- 리포트 아래에 `⚠️ SH 조회 실패`: SH 홈페이지 점검 중이거나 게시판 구조가 바뀐 경우입니다. 구조가 바뀌었다면 `SH_ROW_RE`를 고쳐야 합니다.
- 같은 공고가 매일 새 공고로 뜸: 실행 로그에서 "공고 기록 복원"과 "공고 기록 저장" 단계가 성공했는지 보세요.
- `--get-chat-id`에 아무것도 안 나옴: 봇에게 메시지를 먼저 보내야 합니다.
- 봇이 메시지를 못 보냄: 실행 로그의 `텔레그램 전송 실패:` 뒤에 텔레그램이 알려 준 이유가 나옵니다. `chat not found`는 채팅방 ID가 틀린 경우, `bot was blocked by the user`는 봇을 차단한 경우, `Unauthorized`는 봇 토큰이 틀린 경우입니다. 그룹방이라면 봇이 방에서 나갔는지도 확인하세요.
