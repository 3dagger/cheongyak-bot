# cheongyak-bot

[![daily-report](https://github.com/3dagger/cheongyak-bot/actions/workflows/daily-report.yml/badge.svg)](https://github.com/3dagger/cheongyak-bot/actions/workflows/daily-report.yml)

청약홈, LH청약플러스, SH 인터넷청약에 올라오는 분양·임대 공고를 모아서 매일 아침 텔레그램으로 보내 주는 스크립트입니다.

세 사이트를 매일 따로 들어가 보기 번거로워서 만들었습니다. GitHub Actions에서 돌기 때문에 서버나 켜 둔 PC가 없어도 되고, 파이썬 표준 라이브러리만 써서 설치할 패키지도 없습니다.

## 받는 메시지

```
🏠 청약 데일리 리포트 — 2026-10-27 (월)

🆕 새로 올라온 공고 (지난 리포트 이후)
• [서울] ○○자이 (민영 1,024세대)
   특공 11-03 · 1순위 11-04~11-05 · 공고
   👶 신생아 52세대 · 신혼 104세대
• [경기] △△ 행복주택 입주자 모집 (LH 행복주택)
   마감 11-10 · 공고

👶 신생아·신혼 특공 접수 예정 (14일 내)
• [서울] ○○자이 (민영 1,024세대)
   특공 11-03 · 1순위 11-04~11-05 · 공고
   👶 신생아 52세대 · 신혼 104세대

📬 오늘 접수 시작
• [인천] □□ 민간임대 (공공지원민간임대 512세대)
   접수 10-27~10-29 · 공고
   👶 신혼 60세대

⏰ 마감 임박 (오늘·내일)
• [경기] ◇◇아이파크 (오피스텔 120세대)
   접수 10-24~10-28 · 공고
```

섹션별로 이렇게 고릅니다.

- 새로 올라온 공고: 지난 리포트 이후 처음 보이는 공고입니다. 하루 실행이 빠지거나 API에 공고가 늦게 올라와도 다음 리포트에 나옵니다.
- 신생아·신혼 특공 접수 예정: 신생아·신혼부부 특별공급 물량이 있고, 14일 안에 접수가 시작되는 단지입니다.
- 오늘 접수 시작: 특공, 1순위, 일반 접수 중 하나라도 오늘 시작하는 단지입니다.
- 마감 임박: 접수 마감일이 오늘이나 내일인 단지입니다.

"공고"는 원문 링크입니다. 소식이 없는 날에는 "소식 없음" 한 줄만 옵니다.

## 어디서 가져오나

| 출처 | 대상 | 방식 |
|---|---|---|
| 청약홈 | APT(민영·국민·신혼희망타운), 무순위·잔여, 임의공급, 오피스텔·도시형, 공공지원 민간임대 | 공공데이터포털 API |
| LH청약플러스 | 분양주택, 임대주택(행복·국민·영구·매입·전세 등), 주거복지 | 공공데이터포털 API (토지·상가 제외) |
| SH 인터넷청약 | 분양·임대 게시판의 입주자 모집 공고 | 게시판 HTML 파싱 (지역 필터에 서울이 있을 때만) |

LH 공고는 상세정보 API로 공급 대상별 접수일(특공·일반 등)과 신생아·신혼 특공 여부를 가져옵니다. 세대수는 나오지 않아서 "신생아 특공"처럼 있다는 것만 표시합니다. LH 공공분양은 청약홈에도 올라오는데, 같은 단지는 하나로 합쳐서 세대수는 청약홈, 접수 일정은 LH 것을 씁니다.

SH 공고는 게시일만 알 수 있으니 접수 일정은 공고문에서 확인해 주세요.

## 설치

필요한 것은 GitHub 계정, 공공데이터포털 계정, 텔레그램입니다. 키 승인 대기 시간을 빼면 15분 정도 걸립니다.

### 1. 레포 가져오기

이 레포를 Fork 합니다. 포크한 레포에서는 Actions가 기본으로 꺼져 있으니, Actions 탭에 들어가서 워크플로를 켜 주세요.

공고 기록을 남에게 보이고 싶지 않다면 클론한 뒤 본인 private 레포로 올려도 됩니다. 하루 1분 정도라 무료 사용량 안에서 충분히 돕니다.

```bash
git clone https://github.com/<본인 계정>/cheongyak-bot.git
cd cheongyak-bot
cp .env.example .env
```

### 2. 공공데이터포털 API 키

[공공데이터포털](https://www.data.go.kr)에 로그인한 뒤 아래 세 서비스를 각각 활용신청합니다. 모두 자동 승인입니다.

- [한국부동산원_청약홈 분양정보 조회 서비스](https://www.data.go.kr/data/15098547/openapi.do)
- [한국토지주택공사_분양임대공고문 조회 서비스](https://www.data.go.kr/data/15058530/openapi.do)
- [한국토지주택공사_분양임대공고별 상세정보 조회 서비스](https://www.data.go.kr/data/15057999/openapi.do)

인증키는 계정에 하나라서 세 서비스가 같은 키를 씁니다. 마이페이지에서 일반 인증키의 **Decoding** 값을 복사해 `.env`의 `CHEONGYAK_SERVICE_KEY`에 넣습니다. Encoding 값을 넣으면 두 번 인코딩돼서 인증 에러가 납니다.

신청 직후에는 "등록되지 않은 인증키" 에러가 날 수 있습니다. 보통 1~2시간 안에 풀립니다.

### 3. 텔레그램 봇

1. 텔레그램에서 [@BotFather](https://t.me/BotFather)에게 `/newbot`을 보내 봇을 만들고 토큰을 받습니다.
2. 토큰을 `.env`의 `TELEGRAM_BOT_TOKEN`에 넣습니다.
3. 방금 만든 봇과 대화를 열어 아무 메시지나 보냅니다.
4. 아래 명령으로 채팅방 ID를 확인해서 `TELEGRAM_CHAT_ID`에 넣습니다.

```bash
python3 cheongyak_report.py --get-chat-id
```

가족과 같이 받고 싶으면 그룹방을 만들어 봇을 초대하고, 그룹방에 `/start`를 보낸 뒤 같은 명령을 실행하면 됩니다. 봇은 그룹에서 `/`로 시작하는 메시지만 받기 때문에 일반 메시지로는 ID가 안 잡힙니다. 그룹방 ID는 `-`로 시작합니다.

여기까지 됐으면 로컬에서 먼저 확인해 봅니다.

```bash
python3 cheongyak_report.py --test      # 텔레그램으로 테스트 메시지
python3 cheongyak_report.py --dry-run   # 보내지 않고 리포트를 터미널에 출력
```

### 4. GitHub Secrets 등록

포크한 레포의 Settings → Secrets and variables → Actions에서 `.env`와 같은 값으로 세 개를 등록합니다.

| 이름 | 값 |
|---|---|
| `CHEONGYAK_SERVICE_KEY` | 공공데이터포털 Decoding 키 |
| `TELEGRAM_BOT_TOKEN` | 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 채팅방 ID |

`gh` CLI를 쓴다면 이렇게 해도 됩니다. 실행하면 값을 입력하라고 나옵니다.

```bash
gh secret set CHEONGYAK_SERVICE_KEY -R <본인 계정>/cheongyak-bot
gh secret set TELEGRAM_BOT_TOKEN -R <본인 계정>/cheongyak-bot
gh secret set TELEGRAM_CHAT_ID -R <본인 계정>/cheongyak-bot
```

### 5. 지역 정하고 첫 실행

받을 지역은 레포 변수 `AREA_FILTER`로 정합니다. 변수가 없으면 `서울,경기,인천`입니다. 다른 지역을 받으려면 Settings → Secrets and variables → Actions의 Variables 탭에서 `AREA_FILTER`를 만들고, 전국을 받으려면 값을 `전국`으로 둡니다.

```bash
gh variable set AREA_FILTER -R <본인 계정>/cheongyak-bot --body "부산,경남"
```

워크플로 파일을 고치지 않으니 원본 레포의 변경을 Sync fork로 받을 때 충돌이 나지 않습니다.

그다음 Actions 탭에서 daily-report를 골라 Run workflow를 누르거나, 아래 명령으로 바로 한 번 보내 봅니다.

```bash
gh workflow run daily-report.yml -R <본인 계정>/cheongyak-bot
```

이후로는 매일 아침 자동으로 옵니다. 예약 시각은 07:17(KST)이고, GitHub 사정에 따라 더 늦게 올 수 있습니다.

## 설정

로컬에서는 `.env`, Actions에서는 같은 이름의 레포 변수(Variables)로 바꿉니다.

| 이름 | 기본값 | 설명 |
|---|---|---|
| `AREA_FILTER` | `.env`: 비어 있음(전국)<br>Actions: `서울,경기,인천` | 쉼표로 구분한 시·도. 예: `서울,경기,인천`. `서울특별시`·`경기도`처럼 써도 됩니다. `전국`이라고 쓰면 거르지 않습니다. LH의 "전국" 공고는 항상 포함됩니다. 알아보지 못한 이름은 리포트 아래에 ⚠️로 알려 줍니다 |
| `SEND_WHEN_EMPTY` | `true` | `false`면 소식이 없는 날에는 보내지 않습니다 |

받는 시간은 워크플로의 `cron`으로 바꿉니다. UTC 기준이라 한국 시간에서 9시간을 빼야 합니다. 오전 6시 30분에 받으려면 `30 21 * * *`입니다. GitHub 예약 실행은 부하가 높으면 늦게 돌고 매시 정각에 특히 몰리니, 분은 0이 아닌 값으로 두세요. 이 레포도 08:00 정각 예약이 몇 시간씩 밀려서 07:17로 옮겼습니다.

## 동작 방식

[cheongyak_report.py](cheongyak_report.py) 한 파일이 전부입니다.

1. 청약홈 API 5종에서 최근 45일, LH API에서 최근 90일 공고를 가져오고 SH 게시판 첫 페이지를 읽습니다.
2. `AREA_FILTER`로 지역을 거릅니다.
3. 아직 접수가 끝나지 않은 공고는 한 번 더 조회합니다. APT와 공공지원 민간임대는 주택형별 API로 신생아·신혼 특공 세대수를 합치고, LH는 상세정보 API로 접수 일정을 가져옵니다.
4. 보낸 공고 기록(`.state/seen.json`)과 비교해 새 공고를 고르고, 나머지 섹션을 날짜 기준으로 나눠 텔레그램으로 보냅니다. 메시지가 길면 나눠 보냅니다.

몇 가지 덧붙이면 이렇습니다.

- 보낸 공고 기록은 Actions 캐시로 다음 실행에 넘어갑니다. 캐시가 없는 첫 실행에는 공고일이 어제·오늘인 공고를 새 공고로 봅니다.
- LH나 SH 조회가 실패하거나 결과가 0건이면 리포트는 그대로 보내고 맨 아래에 ⚠️ 경고를 붙입니다.
- 청약홈 조회 실패처럼 리포트를 아예 만들지 못하면 "청약 리포트 생성 실패" 메시지와 실행 로그 링크를 보냅니다.
- GitHub는 60일 동안 커밋이 없는 레포의 예약 워크플로를 끕니다. 그래서 실행할 때마다 `gh workflow enable`로 다시 켜 둡니다.

## 문제 해결

리포트가 안 오면 먼저 Actions 탭의 실행 로그를 봅니다. 포크 직후라면 Actions가 꺼져 있을 가능성이 큽니다.

- "등록되지 않은 인증키" 또는 401: 활용신청 후 아직 반영이 안 된 경우가 대부분입니다. 한두 시간 기다려 보고, 그래도 안 되면 Decoding 키를 넣었는지 확인하세요. 개발계정 활용기간(24개월)이 끝나도 같은 에러가 나니 마이페이지에서 연장하면 됩니다.
- 리포트 아래에 `⚠️ LH 조회 실패`: LH 분양임대공고문 조회 서비스를 활용신청했는지 확인하세요.
- 리포트 아래에 `⚠️ LH 접수 일정 조회 실패`: LH 상세정보 조회 서비스를 활용신청했는지 확인하세요. 그동안 LH 공고는 마감일만 나옵니다.
- 리포트 아래에 `⚠️ SH 조회 실패`: SH 홈페이지 점검 중이거나 게시판 구조가 바뀐 경우입니다. 구조가 바뀌었다면 `SH_ROW_RE`를 고쳐야 합니다.
- 같은 공고가 매일 새 공고로 뜸: 실행 로그에서 "공고 기록 복원"과 "공고 기록 저장" 단계가 성공했는지 보세요.
- `--get-chat-id`에 아무것도 안 나옴: 봇에게 메시지를 먼저 보내야 합니다.
- 봇이 메시지를 못 보냄: 봇을 차단했거나, 그룹방이라면 봇이 방에서 나간 경우입니다.
